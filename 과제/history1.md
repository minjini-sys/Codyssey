## 진행 과정

1. 미션별 데이터파일을 내려받고 원본을 보존했다. 1-2·1-3·1-4는 1-1 결과물을 이어 쓰는 과제가 아니라 각각의 제공 샘플로 수행했다.
2. 사용자가 S/A/B/C/D, 영화 제목 추가, 버튼 이동, 브라우저 저장의 개인용 구성을 선택했다. 그 결정을 기획서에 반영했다.
3. Codex로 A를 제작하고 사용자 허락을 받아 Gemini의 새 대화에 같은 기획 조건을 전달했다. 두 서비스에 보낸 문장을 글자 단위로 동일하게 맞춘 실험은 아니다. Gemini 다운로드 원문과 생성 화면을 보존했다.
4. 미션 2의 카드 생성 코드는 `data-id`에 제목을 따옴표 없이 넣고 있었다. 공백이 있으면 식별자가 끊어지는 문제를 찾고 `dataset.id`와 `textContent`로 대체했다. 화면·다른 기능은 유지했다.
5. 민수의 기획서와 HTML을 먼저 검사한 뒤 받은 피드백을 읽었다. 저장 누락 지적은 맞았지만 '초기화해도 추가 영화가 남는다'는 지적은 실제 코드와 달랐다. 빈 제목 문제와 '기획서 위반' 주장은 구분했다.
6. 미션 4는 칸별 개수 표시 하나만 추가했다. 기존 이동·저장 로직은 바꾸지 않았다. 기존 기능이 망가진 증거가 없어 실패본·복구 이력을 임의로 만들지 않았다.

## 검증 방법과 결과

`node 과제/검증.cjs`는 원본과 결과물 스크립트를 Node.js의 vm 및 최소 DOM/저장 모형으로 실행한다. 실행 결과는 `검증결과.json`에 기록한다.

- 미션 2 원본: 공백이 있는 세 제목의 이동이 실패했다. 콜론이 있어도 공백이 없으면 이동하여, 콜론 자체가 원인은 아니었다.
- 미션 2 수정본: 기본 8개, 공백·콜론·따옴표·태그 형태의 추가 제목에서 이동 검사 통과. 저장 모형 재실행·빈 제목·초기화도 통과했다.
- 미션 3: 저장 모형을 유지해도 재실행 시 초기 상태가 됐다. 공백 입력으로 빈 카드가 생겼다. CSS의 960px 고정 폭과 가로 넘침 숨김은 좁은 화면 문제의 원인 후보로 기록했다.
- 미션 4: 원본과 추가본의 기존 기능 검사를 수행했다. 개수는 초기 0/8 → S 이동 후 1/7 → 제목 추가 후 1/8 → 초기화 0/8이었다.
- 미션 1: A/B의 기본 초기화·이동·추가·저장 모형 재실행·공백 입력을 검사했다. A와 B의 이동 입력 방식은 달라서 동일한 실제 브라우저 클릭 비교로 보완해야 한다.

검사 도구의 최초 실행에서는 정적 aria-label과 template 카드 class를 모형에서 누락했다. 모형을 수정해 다시 실행했으며, 이 도구 오류를 과제 프로그램의 결함으로 기록하지 않았다.

## 아직 수행하지 않은 것

브라우저 도구가 로컬 `file:` 주소의 열기와 관찰을 거부하여 실제 브라우저 사용 검증은 수행하지 못했다. 다른 경로로 우회하지 않았다. 따라서 화면 크기·실제 드래그·파일 재개방 결과를 확인했다고 기록하지 않았다.

GitHub에는 현재 존재하는 결과물과 실제 수행 기록을 등록한다. 실제 브라우저 비교, 일부 주요 대화 캡처와 동료평가 PASS는 남아 있다. 상세 항목은 [제출 확인표](제출_확인표.md)에 있다. 선택 코랩·동료 피드백·실제 PASS를 받은 것으로 꾸미지 않았다.
