# 미션 3 기록

검증 범위: 코드 검토와 DOM 모형 검사. 실제 브라우저 사용·모바일 화면 관찰은 수행하지 않았다. 의견별 확인 방법을 구분해 기록한다.

## 받은 피드백을 열기 전 독립 확인

`민수_기획서.md`와 HTML을 먼저 읽고, `받은_피드백.md`는 자동 검증을 수행한 뒤 열었다.

- 모형에서 기생충을 S로 옮겼다. 이동은 정상이며 한 칸에만 있었다.
- 새 제목을 추가하고 공백만 추가했을 때 빈 카드도 생겼다.
- 저장 모형을 유지한 새 실행에서 초기 8개/미분류로 돌아왔다. 원본에는 저장·불러오기 코드가 없다.
- CSS에서 `.page { width: 960px; }`, `body { overflow-x: hidden; }`를 발견했다. 좁은 화면에서 오른쪽이 잘릴 가능성이 크다. 실제 화면 확인은 못했다.

## 의견별 판단

| 받은 의견 | 확인 결과와 방법 | 반영 / 보류 / 되묻기 | 이유 / 물을 질문 |
|---|---|---|---|
| AI: 저장 기능이 없다 | 저장 코드 부재. 모형 재실행 시 새 영화와 등급이 사라짐 | 반영 | 같은 파일을 다시 열어도 영화·등급 유지라는 명시 기준에 어긋남 |
| AI: 처음으로가 추가 영화를 지우지 않는다 | reset은 `state = fresh()`로 완전히 교체. 자동 검증에서 8개만 남음 | 보류 | 실제 코드·모형과 반대. 원본은 추가 영화를 제거함 |
| AI: 빈 제목이 생겨 기획서를 어긴다 | 모형에서 공백 입력 시 빈 카드 1개 생성 | 반영(개선점만) | 빈 카드 방지는 유용하지만 민수 기획서에는 빈 제목 금지 조항이 없으므로 '기획서 위반'이라는 단정은 수정해야 함 |
| AI: 나머지 기준은 모두 지킨다 | 960px 고정 폭과 가로 넘침 숨김 발견 | 보류 | 좁은 화면 기준을 놓쳤음. 실제 화면 확인도 필요 |
| 동료: 등급 색이 구분되어 좋다 | CSS에 등급별 서로 다른 색 지정 | 반영(좋은 점) | 구분을 돕는 설계. 실제 가독성은 화면 확인 필요 |
| 동료: 분류 진행 수가 좋다 | render에서 전체 수와 분류 수를 매번 계산 | 반영(좋은 점) | 진행 상태를 알 수 있음. 화면 표시 추가 확인 필요 |
| 동료: 끌 때 칸 색이 바뀐다 | dragover/dragleave에 is-over 클래스와 배경 스타일 있음 | 반영(좋은 점, 잠정) | 구현은 확인. 실제 드래그 체감은 미확인 |
| 동료: 휴대폰에서 불편하다 | 고정 폭·overflow 숨김으로 좁은 화면 기준 위반 가능성 확인 | 반영(잠정) | 360px/390px 등 실제 화면에서 잘림 확인 후 확정 |
| 동료: 옮기기가 처음에 헷갈린다 | 어떤 행동·상태인지 특정되지 않음 | 되묻기 | 어떤 영화를 클릭/끌기 했고 어느 순간에 예상과 달랐나요? 선택 강조와 안내 문구를 보셨나요? |
| 동료: 아래 미분류에서 S까지 끌기 어렵다 | DOM에서 미분류가 네 등급 아래에 있음. 클릭 후 등급 버튼 이동도 구현됨 | 되묻기 | 사용한 화면 크기·입력 장치는 무엇이며, 클릭 이동으로도 어려웠나요? 실사용 재현 후 배치 변경 판단 |
| 동료: 카드 색이 칙칙하다 | 미적 선호 의견. 기능 오류 증거 없음 | 보류 | 취향 문제여서 민수의 선호를 먼저 확인 |
| 동료: 포스터 사진 추가 | 현재 기획의 필수 요구 아님 | 보류 | 필요한 이미지 자료·파일 구성을 추가해야 함. 단일 HTML 조건 안에서 가능 여부와 우선순위 먼저 확인 |
| 동료: C칸 제거 | 기획서가 S/A/B/C를 명시 | 보류 | 목적과 합의한 등급을 임의로 바꾸지 않음 |
| 동료: 큰 문제 없으니 PASS | 제공된 시나리오 속 의견일 뿐 실제 평가가 아님 | 보류 | 저장 기준 불충족을 해결해야 함. 실제 플랫폼 PASS를 받은 것으로 기록하지 않음 |

- 아무도 말하지 않았는데 찾은 것: 좁은 화면 문제의 구체적 원인인 960px 고정 폭과 가로 넘침 숨김. 동료가 현상은 말했지만 원인은 설명하지 않았다.
- 선택 코랩: AI 지적이 그럴듯해도 원본의 초기화 동작을 확인해야 한다는 점을 논의하고 싶다.
